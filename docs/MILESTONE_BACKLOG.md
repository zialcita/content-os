## 2. Execution rules and ticket notation

- Dependency order is explicit below. A ticket begins only after its listed prerequisites have usable artifacts; a milestone gate remains open if any required local/live/human proof is missing. Independent account discovery starts in M0, not M5.
- **S / A / U / W** mean schema/persistence, API/event contracts, user interface, workers/side effects. Named entities refer to the proposed `cos_v6` catalog. `none` means no implementation change required in that layer, not omission of a relevant requirement.
- **L** = deterministic local tests on disposable PostgreSQL, contract tests, controlled fault injection; **V** = authorized real provider/account/environment proof; **H** = human/owner/editorial/operational decision. L never substitutes for V/H where required. Local fault fixtures must visibly identify simulation and cannot settle LIVE spend.
- Every completion requires changed-file list, exact commit/branch, fixture hash, executable test command and result, database/version, mode, assertions and evidence links in BUILD_LOG/CURRENT_STATE. API schemas/events must be frozen and validated **before the matching UI** (v6 §16). Typed errors, exact-version approvals, tenant guards and idempotency are part of every vertical slice, not end-stage polish.
- Store future evidence at `docs/evidence/mN/<ticket-or-AT>/<run-id>/`; the paths below are **required future artifacts, not files claimed to exist**. Redact tokens, signed URLs, personal data and secrets; retain object hashes and authorized durable references.
- No generic green unit suite can close a ticket without its stated persisted-state assertion and required end-to-end evidence. A live provider failure is a blocker, never permission to swap in simulated success, a different social account, or an export.
