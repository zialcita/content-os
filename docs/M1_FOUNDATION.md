## Security boundary actually implemented

- The migration creates `cos_foundation_runtime`, a non-login, non-superuser, non-BYPASSRLS group. Runtime login roles created by test fixtures are individually bound to users through the private `database_principals` table.
- A fixed-search-path security-definer `actor()` resolves **`session_user`**, never a body-supplied actor UUID or user-writable custom GUC. Runtime cannot read/write that binding table or users/identities. There is no general service identity bypass and no public context setter. `SET ROLE` does not change the authenticated `session_user`.
- This is a **local database-authenticated principal bridge**, not an OIDC token verifier. Test identities use `https://fixture.invalid` issuer/subject records provisioned by the local migration administrator. They are not real people. Production OIDC signature/issuer/audience/nonce validation, sessions and safe shared-pool actor establishment remain unimplemented gates.
- Active users need a verified timestamp and an identity row for authorization. `(issuer,subject)` is unique. Email does not participate in identity linking. ACTIVE workspace ownership is a deferred same-workspace membership FK plus active verified owner/user/identity validation. Pending/unclaimed workspaces have no implied owner and are inaccessible to runtime users. No production seed/invitation/claim flow exists.
- Roles are explicit lowercase `admin`, `editor`, `reviewer`, `publisher`, `viewer`, with no `owner` value and no duplicate/null roles. Owner authority comes only from `owner_membership_id`. Revoking the active owner's membership fails. Runtime cannot change the owner pointer. **Transfer with target acceptance is not implemented; it fails closed because there is no runtime transfer entrypoint.**
- Non-owners, including admins, need explicit active grants for brand reads and local job creation. Management permission is distinct from brand content permission. Owner/admin can change roles, grants and simulated caps through audited functions. Editor/viewer cannot change budgets or roles. Viewer cannot enqueue.
- Workers authenticate as the original requesting actor. Claim, reservation, intent, completion, recovery and delivery validate that actor and current role/brand access. No worker may act on another person's job merely because it knows job/fence UUIDs. Authorization mutations and worker writes take a workspace lock to serialize permission changes. Only **READ COMMITTED** is supported: central SQL `actor()` and `authorize()` reject other isolation levels, including REPEATABLE READ and SERIALIZABLE, rather than allowing a transaction snapshot to retain revoked grants. This is enforced for direct SQL as well as wrapper callers. `auth_epoch` is not updated or used as a revocation fence in this subset.
- Runtime has **no INSERT/UPDATE/DELETE/TRUNCATE privileges on any foundation table**, including sensitive and dispatch tables. Only an explicit function allowlist is executable. Internal authorization/guard/settlement helpers and trigger functions have no runtime EXECUTE. All current function PUBLIC execution grants are explicitly revoked at the end of the schema migration. The Alembic acceptance audit checks every `cos_v6` routine for PUBLIC EXECUTE (including implicit grants when `proacl` is NULL), and checks effective runtime EXECUTE against an exact-signature allowlist. It runs after each revision inside the migration transaction and again on `upgrade head` reruns. Future migrations must explicitly revoke PUBLIC EXECUTE on every new routine and review any runtime allowlist expansion. **There is no future-default security guarantee:** schema-local default revocation cannot override global PUBLIC defaults; no administrator/global default privileges are changed. The audit detects unsafe grants; it does not silently repair them. Table creation in `cos_v6` is not granted.
- Real PostgreSQL **ENABLE RLS** SELECT policies enforce runtime tenant/brand reads. Missing binding denies. Tests query through separate non-owner, non-BYPASSRLS login connections, including pooled reuse and GUC spoof attempts; they do not merely claim RLS because an administrator query had a tenant filter. No INSERT/UPDATE RLS policies exist because all direct runtime DML is revoked.
- **FORCE RLS is not installed.** Security-definer functions intentionally execute with table-owner authority, then explicitly authorize the session-bound actor. Local migrations use pgserver's administrator, not a claimed production least-privilege migrator. Production ownership/definer role separation, FORCE-RLS strategy and production pool integration remain an M1 security gate; this subset must not be presented as full production tenant-isolation acceptance.

The migration requires permission to create the dedicated group role. A pre-existing group/schema collision fails closed rather than silently trusting its privileges. Do not attach this module to a production/shared database without a reviewed role provisioning and migration procedure.

## Durable jobs, event delivery and budget mechanics

All public operations are SQL functions called through the small SQLAlchemy `foundation.service.call` wrapper; caller owns the transaction and must configure **READ COMMITTED before beginning it** (for example, SQLAlchemy `create_engine(..., isolation_level="READ COMMITTED")`). Unsupported isolation raises SQLSTATE `25001`; roll back and start a supported transaction, do not retry within the rejected transaction. The wrapper does not import application config, dotenv, provider adapters, or legacy database initialization.

1. `enqueue` binds a workspace, real brand, original member, logical operation UUID and 32-byte input hash. Matching replay returns the same job; changed hash/brand/actor conflicts. One local step is created transactionally.
2. `claim` uses `FOR UPDATE SKIP LOCKED`, sets RUNNING, increments its fencing token, and records lease owner/expiry/heartbeat. Lease duration is bounded to 1–300 seconds. Claiming a locked step skips it. Heartbeat and all worker-authoritative writes require matching owner/token and an unexpired lease. NULL lease durations, owners and tokens are explicitly rejected in claim/heartbeat/fence validation. Step constraints require a paired lease owner/expiry exactly while RUNNING, with a non-NULL heartbeat. Invalid inputs leave step/job/history rows unchanged.
3. `reserve` checks both explicit workspace and job accounts under ordered locks, creates one immutable allocation per cap, and increments both counters atomically. Missing accounts fail closed. All money is signed-width bigint micro-units with an ISO currency check; reservation/settlement values in this subset must be nonnegative. Zero is a hard zero. `numeric` intermediate comparisons avoid bigint overflow in cap arithmetic. This is **two-cap simulated accounting**, not full campaign/plan/authorization cap enforcement.
4. Replaying the same step reservation returns its original reservation; changed amount/currency conflicts. `release_reservation` is exactly-once and allowed only before any submit intent. `complete` settles once, records one ledger entry with per-account usage allocations, writes SUCCEEDED and the outbox event in the same transaction. Truthful simulated overrun above the cap is recorded and blocks future reservations; it is not discarded to make cap totals appear valid. Rebuild tests compare each account against immutable allocations without double-counting hierarchical caps as provider charges.
5. `record_intent` persists a **local simulated attempt**. Once an intent exists, neither blind resubmission nor release is allowed. A process dies with `os._exit(23)` after committing an intent in acceptance; a fresh process/connection recovers it as RECONCILING, retains the reservation, increments the fence, and never claims it as queued work. Expired work without intent can safely return to QUEUED. No operator reconciliation-result/resubmission workflow is implemented; uncertain work remains blocked.
6. `consume` combines inbox uniqueness/hash comparison, completion, ledger and outbox in one transaction. Duplicate delivery yields one effect, including two simultaneous connections. A same-ID/different-hash event conflicts. Invalid inbox insert rolls back all business/accounting/event changes. This is an internal local-fixture consumer, **not a verified provider webhook**.
7. `claim_event`/`ack_event` provide bounded leased/fenced outbox delivery. Expired deliveries can be reclaimed; stale acknowledgment fails. Transport may be at least once; inbox effects are deduplicated. NULL duration/owner claims and NULL owner/token acknowledgments fail without changing the event. Outbox constraints require a paired non-NULL owner/expiry exactly while DELIVERING; PENDING/DELIVERED rows cannot carry leases. There is no network relay in this slice.
8. `job_transitions` records initial/changed step states. Audit, ledger, allocation, transition, processed inbox and outbox deletion are protected by immutable-history triggers in addition to runtime privilege revocation; outbox business payload is immutable while delivery fields can change through the fenced routines.

The workspace authorization lock is deliberately coarse: writes in one workspace serialize, while locked step selection still uses SKIP LOCKED. This is a bounded correctness implementation, not a throughput benchmark. The job/step state matrix is only QUEUED/RUNNING/RECONCILING/SUCCEEDED; cancellation, safe retry rules, multi-step dependencies and aggregate partial success remain future work.

## Absolute live-spend boundary

Every enabled job has `execution_mode=SIMULATED`, `paid_authority=NONE`, `scope_type=BRAND`, `job_kind=LOCAL_SIMULATION`, and `originating_operation_id=foundationSimulation`. Attempt provider is `local_fixture`. Budget accounts, reservations and ledger also CHECK `SIMULATED`; there is no live dispatch function, no provider import, and no externally usable HTTP endpoint. A positive fixture cap is **not** a live authorization. Simulated usage rows cannot be relabeled LIVE. Customer credits, signed adjustments/refunds, real provider billing/finality, capacity slots and production/preproduction authority branches are **not** implemented. Unrepresentable bigint totals fail closed; handling out-of-range real-provider bills is not established.

## Proposed ADR 0002 amendments / bounded-slice differences

These are implementation-scoping proposals, not edits to or acceptance of the full ADR:

1. Introduce temporary migration-private `database_principals` for strong local runtime tests using session-user bindings. Do not adopt per-user database accounts as the production OIDC architecture without review. Replace/bridge with a trusted authenticated context mechanism before API integration; never downgrade to an arbitrary user GUC.
2. Enable only the explicitly named LOCAL_SIMULATION operation in this revision. No workspace-null execution branch, campaign/plan jobs, typed inputs/outputs, work authorizations, or paid execution are enabled. Same-workspace same-job composite FKs remain real; brand is mandatory here, so nullable-brand MATCH SIMPLE holes are not introduced. Later revisions must implement the full W-root scope allowlist and null-safe child consistency before enabling workspace administration.
3. Start with fixed-lifetime workspace/job simulation accounts, not the planned campaign/plan/preproduction period/cap system. No budget period rollover, credit dimension or FX alias is implemented. Keep the planned table names and widen by future migration only alongside authorization tests.
4. Step scope is normalized through the real same-job FK rather than duplicating all future E metadata on each child now. Only the one root scope/kind is allowed. Full mutable scope/type/authority consistency validators are still required when additional job kinds are introduced.
5. Preserve the owner bypass only inside tightly scoped definer functions; production FORCE-RLS/role ownership hardening remains open rather than asserting a cosmetic FORCE setting proves safety.
6. Refuse all downgrades, including empty scaffolding. This is stricter than the proposed optional empty-schema rollback and protects history by default.
